System Architecture

Factory Inventory Management System

A full-stack demo application: a Vue 3 single-page frontend backed by a Python FastAPI service, serving in-memory mock data loaded from JSON files (no database).

Tech Stack

Three layers: browser client, API server, and static JSON data.

Frontend

Vue 3 + Vite

  • Vue 3 (Composition API)
  • vue-router 4 — client-side routing
  • axios — HTTP client
  • Vite — dev server & bundler
  • Runs on localhost:3000
Backend

Python + FastAPI

  • FastAPI — REST API framework
  • Pydantic — request/response validation
  • Uvicorn — ASGI server
  • uv — dependency management
  • Runs on localhost:8001
Data & Tests

Mock JSON + pytest

  • 7 JSON files in server/data/
  • Loaded into memory at startup
  • No persistence — resets on restart
  • pytest + httpx for API tests

Data Flow

How a filter change on screen turns into rendered data.

Filter selected

User picks a Time Period, Warehouse, Category, or Order Status in the shared FilterBar.

Shared state updates

The useFilters composable holds the selection in module-scoped refs, shared across all views.

API request

api.js sends the filters as query params to the matching FastAPI endpoint.

Server-side filtering

FastAPI filters the in-memory lists (skipping any filter set to "all") and validates the result against a Pydantic model.

Reactive render

The response populates a raw data ref (e.g. allOrders); computed properties derive totals and chart data for the view.

Known Gaps

Observed while reviewing the code — useful context if you extend this app.

Dangling frontend calls: client/src/api.js defines task CRUD calls (getTasks, createTask, etc.) and purchase-order calls (createPurchaseOrder, getPurchaseOrderByBacklogItem) with no matching routes in server/main.py. Tasks are currently mocked entirely in the useAuth.js composable. The Backlog.vue view also exists but isn't registered in the router.
